Register the five TTS reading-highlight tokens as `component-public`, and state the contract on the package-private hooks two READMEs already offered to hosts.

`--pie-tts-word-highlight`, `--pie-tts-sentence-highlight`, `--pie-tts-line-highlight`, `--pie-tts-word-underline` and `--pie-tts-word-shadow` were held out of the registry by the allowlist in `check-theme-tokens.mjs` and named in no package README, while the client-facing Angular host declares all five in `themes.scss`. Undocumented API in practice: a host reading `token-registry.json` to learn what it may set could not see them, and the consumer pad already records them as silent-breakage surfaces. They are now registry entries under a `tts-highlight` category, owned by `@pie-players/pie-assessment-toolkit`, `documentedIn` its README, with `excluded` scheme participation — `HighlightCoordinator` derives each value from the resolved theme at runtime, so no scheme value applies.

The new README block records the derivation and the override cost. The coordinator writes all five inline on the document element, which outranks any author selector, so a host override takes `!important` — which is how the Angular host sets them — and forfeits the adaptive contrast the derivation maintains across schemes. Nothing about the write path, the token names, the fallbacks or the rendered highlights moves here; this registers and documents what already ships.

The same registry-versus-README audit found the reverse problem in two packages: `calculator-cortex/README.md` offers `--pie-calculator-surface` and `--pie-calculator-surface-raised` as "package hooks" and `tool-tts-inline/README.md` offers seven panel-chrome hooks, all unregistered, with no statement of what a host may rely on. Each README now says they carry no compatibility guarantee, matching what `tool-line-reader/README.md` already states for `--pie-tool-line-reader-outline-color`. Four more allowlist entries are dropped as dead weight. `--pie-annotation-underline` and `--pie-annotation-underline-dark` have been registered `component-public` for some time, so the gate never reached their allowlist lines. `--pie-tts-trigger-shadow` appears in no source file. `--pie-elements-ng-root` is a CLI flag for `scripts/smoke-pie-elements-ng-esm.mjs` that was never a CSS token; the gate does not scan the files it appears in, so nothing was silencing anything. The allowlist goes from 44 entries to 35, and every remaining one names a token some source file actually reads.
