# External test corpora for the Cortex calculator

This page is for contributors to the Cortex calculator
(`packages/calculator-cortex`). Everything CI runs is committed; this page records
the corpora that are not: data downloaded on demand, and open-source suites read
for their cases but never vendored. It records what each one gave, what it found
and what it did not cover, for whoever next judges whether the calculator is
feature complete.

Nothing here is a dependency. Each entry is either regenerated by a script in the
repository or was consulted once by hand.

## GSM8K (on demand, outside CI)

- Source: `openai/grade-school-math`, `grade_school_math/data/train.jsonl`
- License: MIT
- Size: 4.2 MB, 7473 problems, 23716 calculator annotations, 10770 distinct and
  well-formed
- Runner: `packages/calculator-cortex/scripts/build-expression-corpus.mjs`

GSM8K's worked solutions carry inline calculator annotations — `<<48/2=24>>` —
authored so a calculator could execute the step. They are expression/result pairs,
not word problems, over `0-9 + - * / . ( )` alone: arithmetic squarely inside basic
mode's capability set. That makes it the one public dataset that is already a
calculator corpus rather than a corpus a model reasons about.

CI runs a committed 300-entry sample under
`packages/calculator-cortex/tests/fixtures/`, selected by a deterministic stride
over the sorted distinct annotations so regenerating produces no diff. The full
10770 are opt-in:

```bash
bun run --filter '@pie-players/pie-calculator-cortex' test:corpus
```

That takes roughly four and a half minutes and asserts 10775 expectations: one
round trip per annotation and five over the whole corpus. The full run stays out
of CI because it costs thirty times the committed sample for coverage of the same
four properties, and because it depends on a network fetch that would degrade
silently when the upstream file moves.

Findings from the full run: no calculator defects. Two annotations are mistyped in
the source data (`180//3`, `560//10`); the generator rejects them as malformed,
so they do not exercise the error path in a suite that checks arithmetic.
Fifty-six of the first fifteen hundred entries disagreed with our answers by
string but not by value, because the annotation authors write currency (`720.00`)
and bare leading points (`.75`), so the property compares numerically.

The annotations are ground truth only up to that formatting. They are also
labeled, which most of the suite does not need: of its four properties, only
"every answer matches its authored result" uses the labels. The other three —
every outcome is a declared error code or an answer, the three capability sets
nest, a displayed answer re-entered answers itself — are claims about this
package's own layering and would hold against any corpus at all.

## Suites read for their cases, never vendored

These were mined by hand. Selected shapes were rewritten as cases in
`packages/calculator-cortex/tests/calculator-cortex-scenarios.test.ts` and the
Playwright suite, `packages/calculator-cortex/e2e/calculator-cortex.spec.ts`; no
file was copied,
and each project tests its own parser, so only the shapes carried over and none of
the expectations did.

| Project | License | What it gave | What it cannot give |
| --- | --- | --- | --- |
| `mathquill` | MPL-2.0 | Keystroke sequences, now the typing tests, which assert only the answer: `/` opens a fraction over what precedes it, `^` a superscript, an unmatched `(` closes itself, the cursor stays in a sub-box until moved out. | Evaluation: it is an editor. Its copyleft is per-file, so cases are derived and never copied. |
| `math-expressions` (Doenet) | GPL-3.0 OR Apache-2.0 | About 400 LaTeX grouping and precedence strings: `-x^2`, `{x^y}^z`, nested `|…|`, bare leading and trailing decimal points, `\cdot`, `\left…\right`, implicit multiplication after a fraction. | Answers: it produces ASTs. Copying under the Apache-2.0 option would need attribution. |
| `perseus` (`math-input`) | MIT | A keypad inventory: 40 keys against Cortex's 33 when diffed. | Calculator arithmetic: it is an answer-entry field whose evaluator compares algebraic equivalence. |
| `mathjax-full` | Apache-2.0 | Nothing: `master` has no test directory, and the `testsuite` branch's 11 files are API plumbing. | — |

The keypad diff found three gaps. Two are closed: the keypad has a stacked-fraction
key and a base-*n* logarithm key, and `\log_{2}(8)` answers 3. The sign key stays
absent by design: in a mathfield `-` is contextual, so Minus on an empty expression
negates, and an e2e test pins that path. Typing `log_2` still produces
`\log_{_2}`, which MathLive nests instead of filling; the scenario table pins that
state.

## Considered and not used

- **MATH** (Hendrycks, MIT, 12500 problems) — answers are LaTeX (`\frac{3}{4}`,
  `2\pi`, `\sqrt{2}`), not values a calculator displays, so it is poor ground
  truth. It is the best available *fuzz* corpus of real LaTeX for
  `validateExpression`, and remains the obvious next source if the policy layer
  needs volume rather than the arithmetic layer.
- **ASDiv, SVAMP, MAWPS, MathQA** (mostly CC-BY) — numeric answers with explicit
  equations, cleaner than GSM8K but an order of magnitude smaller, and MathQA's
  operation DSL would need translating. No coverage GSM8K does not already give.
- Vendoring the full 10770 into the repository. Rejected: a fixture that large is
  not reviewable, the committed sample already exercises the properties it checks,
  and the script regenerates it.
