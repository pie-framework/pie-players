# External test corpora for the Cortex calculator

Everything CI runs is committed. This page records the corpora that are **not**:
data downloaded on demand, and open-source suites read for their cases but never
vendored. It exists so the next person deciding whether the calculator is feature
complete can see what has already been mined, what it found, and what it did not
cover — rather than repeating the survey.

Nothing here is a dependency. Each entry is either regenerated by a script in the
repository or was consulted once by hand.

## GSM8K — run on demand, not in CI

- Source: `openai/grade-school-math`, `grade_school_math/data/train.jsonl`
- License: MIT
- Size: 4.2 MB, 7473 problems, 23716 calculator annotations, 10770 distinct and
  well-formed
- Runner: `packages/calculator-cortex/scripts/build-expression-corpus.mjs`

GSM8K's worked solutions carry inline calculator annotations — `<<48/2=24>>` —
authored so a calculator could execute the step. They are expression/result pairs,
not word problems, over `0-9 + - * / . ( )` alone: arithmetic squarely inside basic
mode's capability set. That makes it the one public dataset that is already a
calculator corpus rather than a corpus a model reasons about.

CI runs a committed 300-entry sample under
`packages/calculator-cortex/tests/fixtures/`, selected by a deterministic stride
over the sorted distinct annotations so regenerating produces no diff. The full
10770 are opt-in:

```bash
bun run --filter '@pie-players/pie-calculator-cortex' test:corpus
```

That takes roughly four and a half minutes and asserts 10775 expectations. The
full run is not in CI because it is thirty times the committed sample's cost for
coverage of the same four properties, and because it depends on a network fetch —
a CI job that silently degrades when an upstream file moves is worse than one that
does not exist.

Findings from the full run: no calculator defects. Two annotations are mistyped in
the source data (`180//3`, `560//10`), which the generator now rejects as
malformed rather than letting them exercise the error path in a suite meant to
check arithmetic. Fifty-six of the first fifteen hundred entries disagreed with
our answers by string but not by value — the annotation authors write currency
(`720.00`) and bare leading points (`.75`) — which is why the property compares
numerically and never by string.

The annotations are ground truth only up to that formatting. They are also
labelled, which most of the suite does not need: of its four properties, only
"every answer matches its authored result" uses the labels. The other three —
every outcome is a declared error code or an answer, the three capability sets
nest, a displayed answer re-entered answers itself — are claims about this
package's own layering and would hold against any corpus at all.

## Suites read for their cases, never vendored

These were mined by hand. Selected shapes were rewritten as cases in
`calculator-cortex-scenarios.test.ts` and the Playwright suite; no file was copied,
and each project tests its own parser, so only the shapes carried over and none of
the expectations did.

| Project | License | What it gave | What it cannot give |
| --- | --- | --- | --- |
| `mathquill` | MPL-2.0 | Keystroke sequences: `/` opening a fraction over what precedes it, `^` opening a superscript, an unmatched `(` closing itself, and the cursor staying inside a sub-box until moved out. Became the typing tests, which assert only the answer. | Nothing about evaluation — it is an editor. Its copyleft is per-file, so cases are derived rather than copied. |
| `math-expressions` (Doenet) | GPL-3.0 OR Apache-2.0 | ~400 LaTeX grouping and precedence strings: `-x^2`, `{x^y}^z`, nested `|…|`, bare leading and trailing decimal points, `\cdot`, `\left…\right`, implicit multiplication after a fraction. | Answers — it produces ASTs. Dual-licensed, so the Apache-2.0 option governs, but attribution would be required to copy. |
| `perseus` (`math-input`) | MIT | A keypad inventory to diff against ours: 40 shipped keys against our 33. | Calculator arithmetic — it is an expression-entry field for answer grading, and its evaluator compares algebraic equivalence. |
| `mathjax-full` | Apache-2.0 | Nothing. Its `master` has no test directory and the `testsuite` branch holds 11 files, all API plumbing. Recorded so nobody looks again. | — |

The keypad diff produced three real gaps rather than scope differences: no sign
key, so a leading `-` is entered through subtraction; no stacked-fraction
template, though `\frac` evaluates when MathLive builds one; and no base-*n*
logarithm key. The last matters because `\log_{2}(8)` now answers 3 while typing
`log_2` produces `\log_{_2}`, which MathLive nests instead of filling — so that
capability is currently reachable only through host-seeded or imported state. Both
states are pinned in the scenario table.

## Considered and not used

- **MATH** (Hendrycks, MIT, 12500 problems) — answers are LaTeX (`\frac{3}{4}`,
  `2\pi`, `\sqrt{2}`), not values a calculator displays, so it is poor ground
  truth. It is the best available *fuzz* corpus of real LaTeX for
  `validateExpression`, and remains the obvious next source if the policy layer
  needs volume rather than the arithmetic layer.
- **ASDiv, SVAMP, MAWPS, MathQA** (mostly CC-BY) — numeric answers with explicit
  equations, cleaner than GSM8K but an order of magnitude smaller, and MathQA's
  operation DSL would need translating. No coverage GSM8K does not already give.
- Vendoring the full 10770 into the repository. Rejected: a fixture that large is
  not reviewable, and the properties it checks are already exercised by the
  committed sample. The script is the artifact worth maintaining, not the data.
